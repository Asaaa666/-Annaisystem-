## 打越祭リアルタイム混雑サイト 管理者向け指南書

この文書は、プログラミングやWebサイト運用の経験がない人が、次年度の管理者を引き継ぐことを想定しています。上から順番に読めば、サイトの仕組み、普段の更新方法、トラブル対応まで確認できます。

## 1. このサイトでできること

来場者が、次の情報をスマートフォンやパソコンで確認できます。

- 団体名や企画名を検索する
- 建物や階を選んで、会場マップを見る
- 団体の場所、紹介文、カテゴリを見る
- 混雑度を5段階で確認する
- 更新された時刻を確認する

管理者が普段行う作業は、主にスプレッドシートの更新です。Webサイトのコードを毎回書き換える必要はありません。

## 2. 最初に覚える言葉

| 言葉 | 意味 |
| --- | --- |
| Webサイト | 来場者がブラウザで見る画面です |
| リポジトリ | このサイトのファイルを保管している場所です |
| React / Vite | 画面を作り、公開用ファイルを作るための仕組みです |
| GAS | Google Apps Scriptの略です。スプレッドシートの情報をWebサイトへ渡します |
| API URL | WebサイトがGASへ情報を取りに行くための住所です |
| デプロイ | 変更したサイトを公開場所へ反映することです |
| `app` フォルダー | 実際のWebアプリが入っているフォルダーです |
| `public` フォルダー | マップやロゴなど、画面で使う画像を置く場所です |

## 3. 全体の仕組み

情報の流れは次のとおりです。

```text
Googleスプレッドシート
	↓
GAS（データをJSON形式で公開）
	↓
Reactアプリ（データを画面に表示）
	↓
Vercelなどの公開サイト
	↓
来場者のスマートフォン・パソコン
```

団体名や混雑状況を変更する場合は、原則としてスプレッドシートを編集します。コードを変更するのは、列の構成を変える、画面のデザインを変える、マップ画像の対応を増やす、といった場合だけです。

## 4. 次年度の引き継ぎで最初にすること

### 4-1. 必要なものを確認する

前任者から、次の4つを受け取ってください。

1. このリポジトリを編集できるGitHubアカウント
2. スプレッドシートを編集できるGoogleアカウント
3. GASのプロジェクトを編集・再デプロイできるGoogleアカウント
4. 公開サイトを管理できるVercelアカウント、またはデプロイ方法

パスワードやアクセストークンはREADMEやチャットに書かず、学校やチームの決められた方法で引き継いでください。

### 4-2. 作業フォルダーを準備する

1. リポジトリをVS Codeで開きます。
2. `app` フォルダーが見えることを確認します。
3. [app/.env.example](app/.env.example) をコピーして、同じ場所に `.env` という名前で保存します。
4. `.env` の年度を次年度に変更します。

```text
VITE_FESTIVAL_YEAR=2027
VITE_GAS_API_URL=前任者から受け取ったGASのWebアプリURL
```

`VITE_GAS_API_URL` は、末尾が `/exec` のURLを使います。URLが分からない場合は、推測して作らず前任者に確認してください。

### 4-3. 最初の動作確認をする

VS Codeのターミナルで、次のコマンドを1行ずつ実行します。

```bash
cd app
npm install
npm run build
```

`built` や `built in` と表示されれば、公開用ファイルの作成に成功しています。エラーが出た場合は、エラー文を省略せず前任者や詳しい人に共有します。

## 5. スプレッドシートの編集方法

このアプリはGASから `groups`、`coords`、`updates` の3種類のデータを受け取ります。1行目は見出しとして読み飛ばされるため、見出しの次の行からデータを入力します。

### 5-1. 団体情報（groups）

列の順番を変えないでください。

| 列 | 内容 | 例 |
| --- | --- | --- |
| A列 | ID | 1 |
| B列 | 団体名 | 生物部 |
| C列 | 紹介文 | 生き物の展示を行います |
| D列 | 場所 | 中学棟 3階 |
| E列 | ロゴ画像のファイル名またはURL | seibutsu.png |
| F列 | カテゴリ | 展示 |

団体を追加するときは、既存の行をコピーしてから内容を書き換えると安全です。団体名は、混雑情報や座標情報の団体名と同じ表記にしてください。余分な空白や表記違いがあると、情報が結びつかないことがあります。

### 5-2. マップ座標（coords）

| 列 | 内容 | 例 |
| --- | --- | --- |
| A列 | 団体名 | 生物部 |
| B列 | 場所・階 | 中学棟 3階 |
| C列 | マップ上のX座標（0〜100） | 77.9 |
| D列 | マップ上のY座標（0〜100） | 44.2 |
| E列 | 旧カテゴリ（現在は基本的に未使用） | 展示 |
| F列 | カテゴリ | 展示 |

X座標は左から右、Y座標は上から下です。新しい団体のピンを置くときは、サイト内の座標測定機能を使える場合があります。測定機能が使えない場合は、既存の座標を参考にして入力し、公開後に位置を確認します。

### 5-3. 混雑状況（updates）

| 列 | 内容 | 例 |
| --- | --- | --- |
| A列 | 更新日時 | 2027/09/20 10:15:00 |
| B列 | 団体名 | 生物部 |
| C列 | 混雑度 | 1〜5、休止中、受付終了 |

混雑度の意味は次のとおりです。

- `1`: とても空いている
- `2`: かなり空いている
- `3`: ふつう
- `4`: かなり混雑
- `5`: とても混雑
- `休止中`: 一時的に案内を停止
- `受付終了`: 売り切れ・配布終了

同じ団体の記録が複数ある場合、サイトには最後の記録が表示されます。入力時刻は、スプレッドシートが自動入力する仕組みなら手で変更しません。

## 6. 画像を追加・変更する方法

### ロゴ画像

1. 画像ファイルを `app/public` に置きます。
2. ファイル名は英数字とアンダースコアを中心にします。例: `seibutsu.png`
3. groupsのE列にファイル名を入力します。
4. その団体名で自動表示されない場合は、`app/src/App.tsx` の `LOGO_ALIAS_MAP` に既存の書き方をまねて追加します。

### マップ画像

1. WebP形式の画像を `app/public` に置きます。
2. `app/src/App.tsx` の `mapImageMap` に、場所の名前とファイル名を追加します。
3. スプレッドシートの場所名と、`mapImageMap` の左側の名前を完全に一致させます。
4. `npm run build` を実行してから公開します。

画像を差し替えたのに古い画像が表示される場合は、ファイル名を変えるか、`MAP_ASSET_VERSION` の値を更新してキャッシュを切り替えます。

## 7. 公開前の確認チェックリスト

- 年度が次年度になっている
- `.env` のGAS URLが正しい
- 団体情報の列順が変わっていない
- 座標情報の団体名と場所が正しい
- 混雑状況の団体名が団体情報と一致している
- ロゴとマップ画像が表示される
- 検索で団体が見つかる
- 場所を選ぶと正しいマップが表示される
- 団体カードを押すと場所と混雑状況が表示される
- `npm run build` が成功する
- 公開後のURLをスマートフォンでも確認する

## 8. よくある問題と対処

### 「団体情報を読み込めませんでした」と表示される

まず通信環境を確認し、ページを再読み込みします。それでも直らない場合は、`.env` のGAS URLが正しいか、GASがWebアプリとして公開されているかを確認します。

### 団体は表示されるが、混雑状況が表示されない

updatesのB列の団体名がgroupsのB列と完全一致しているか確認します。団体名の空白、記号、全角・半角の違いも確認してください。

### マップにピンが表示されない

coordsのA列の団体名、B列の場所、C列とD列の座標を確認します。C列とD列は0〜100の数値にしてください。

### ロゴだけ表示されない

ファイルが `app/public` にあるか、E列のファイル名が正しいか確認します。ファイル名に日本語や空白がある場合は、英数字の名前に変更して再確認します。

### 変更が公開サイトに反映されない

スプレッドシートの変更は、ページを再読み込みして確認します。コードや画像の変更は、`npm run build` 成功後にデプロイが完了しているか確認します。古い画像だけ残る場合はキャッシュの可能性があります。

## 9. 変更してよい場所・避ける場所

### 通常の担当者が変更してよい場所

- スプレッドシートの団体情報
- スプレッドシートの座標情報
- スプレッドシートの混雑状況
- `app/.env` の年度とGAS URL
- `app/public` の画像ファイル

### 理由が分からないまま変更しない場所

- スプレッドシートの列の順番
- GASの返却データの名前（`groups`、`coords`、`updates`）
- `app/src/App.tsx` のデータ取得処理
- `package.json` の依存関係
- 公開URLやGASの権限設定

変更前には必ずコピーを作り、変更後はチェックリストと `npm run build` で確認してください。

## 10. 困ったときに共有する情報

問題を相談するときは、次の情報を一緒に送ると解決が早くなります。

1. 何をしようとしたか
2. どの画面で起きたか
3. 画面に表示されたエラー文
4. 変更したファイルやスプレッドシートの列
5. `npm run build` の結果
6. 問題が起きた公開ページのURL

パスワード、APIキー、アクセストークンは送らないでください。
